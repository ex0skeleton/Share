A quick guide

Send files or a folder

  1. Open ShareWiz on your device.
  2. Use Choose files for individual files, or Choose folder to share a folder with its contents.
  3. Optionally add a password, receiver approval, or expiry.
  4. Press Start sharing. Send the short code or sharing link, or show the QR.
  5. Keep this page open. The highlighted Stop Sharing button immediately revokes access.

Receive directly to storage

  1. Open the sharing link, scan the QR, or enter the eight-character code in Receive.
  2. Enter the password or wait for approval if requested.
  3. Click Download and choose where to save. Files are written in small blocks, without holding the whole download in RAM.
  4. Use Download folder to recreate a shared folder. Download All can save separate files and folders, or one ZIP.
Browser support

Receiving needs a browser that permits writing to a chosen file or folder. Use desktop Chrome or Edge over HTTPS when possible. Many mobile browsers cannot do this. Unsupported browsers can still send, but ShareWiz does not fall back to storing whole downloads in RAM.

A small memory buffer is always necessary. The app has no 100 MB or 200 MB download cap in disk-saving mode. Available disk space, the filesystem and browser still set practical limits.

Folder structure and empty folders

Choose Folder preserves the selected root folder and nested paths. Empty folders are included when your browser supports the full folder picker. If it supplies only a file list, empty folders cannot be detected; ShareWiz tells you when that fallback is used.

The receiver chooses a destination. Existing matching filenames are preserved by using a numbered name for the incoming file. ZIP is optional and also preserves folder structure. Files are bundled without compression.

Resume and interruptions

Keep both tabs open and the original sharing session active. If the network drops, press Resume. Verified blocks and the open disk writer are retained in the receiving tab. Reloading or closing the tab loses resumable progress. Completed files remain saved; a browser may discard an unfinished temporary file.

QR and short codes

Short codes ignore spaces, hyphens and letter case. They are temporary and expire when sharing ends. Anyone who knows the short code can request access. Passwords and receiver approval remain optional.

On HTTPS, the QR contains a link to this app with the share details. A phone’s normal camera can open it. If camera access fails inside ShareWiz, open a QR image or type the code. Camera images stay on your device.

Privacy and connection services

Your selected files stay on the sending device until requested. WebRTC encrypts data, directly or through a relay. GitHub Pages only serves the app. It does not store your shared files. PeerJS and STUN/TURN services help devices connect and see connection metadata. Internet is required, including on the same Wi-Fi; public services have no availability guarantee.

Device names are self-reported. A password, if enabled, is never included in the sharing link. Keep the page visible and your device awake, especially on Android.
